# Experience First

**When:** a product, UX or scope trade-off, and when you report what a change does.

**Rule:** If ease of implementation conflicts with the user's experience, choose the
experience. The user is whoever consumes the work: the end user of a UI, the developer who
imports a library, and the engineer who maintains the code next.

- Each feature, control and option must earn its place. Ship fewer features with finished
  details.
- Tell the effect for the consumer and for the maintainer before any implementation detail.

**You skipped it when:** a report lists the changed files and does not say what changes for
whom, or an option exists because it was easy to add.

**Not:** [Foundational Thinking](foundational-thinking.md) sets the order of the work. This
principle sets the target.
