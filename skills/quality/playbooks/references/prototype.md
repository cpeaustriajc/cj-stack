# Prototype

A prototype answers one design question before any app code. It is throwaway.

1. Name the one question the prototype must answer. If there is no decision to make, skip to
   the feature playbook.
2. Read the design system, the closest existing screen and any decision record for the area.
   Ask what a top designer would show that the request did not name; compare with the taste
   references in `ui-polish`'s `references/quality-bar.md`.
3. Build it as a design artifact, or as plain HTML in `.claude/work/<topic>/`. Use the project's
   kit components and tokens; no app code, tests or abstractions.
4. Put the current design beside each option, each labelled, behind one switcher or as separate
   artboards, following `ui-polish`'s `references/quality-bar.md`.
5. Check it as that reference's "Definition of done" says, then run `ui-polish` on it.
6. Present the options with their tradeoffs and one recommendation, and say it is throwaway.
   The approved option goes to the feature playbook as the design.
